## Ключ связи

- **ID Спасибо** = `users.id` в PostgreSQL приложения «Спасибо» (целое число > 0).
- **Карта Teams** = `public_number` (`MR-00142`), 8-значный `short_code`, хвост ссылки `/c/{token}`.
- ФИО, телефон, ресторан **не используются** для автоматического матча.

В Teams Bonus на держателе карты:

- `users.spasibo_user_id` — строка с ID из Спасибо;
- `users.spasibo_certificate_id` — какую employee-карту показывать в Спасибо.

## Excel: коннект (HR → Teams Bonus)

- Формат: `.xlsx`, лист **`Коннект`** (регистр не важен).
- Лимиты: до 2 МБ, до 1000 строк данных.
- Пример: `/hr/settings/spasibo-connect/sample.xlsx` (в UI Настроек).

### Колонки

| Колонка | Обязательно | Примечание |
|---------|-------------|------------|
| ID Спасибо | да | Алиасы: `id спасибо`, `spasibo id`, `id` |
| Номер карты Teams | да | `MR-…`, short code, token |
| Фамилия | нет | Только предпросмотр |
| Имя | нет | Только предпросмотр |

### Какие карты принимаются

- `ledger_sheet = employee`;
- активная, не удалённая;
- сегмент(ы): «Карта сотрудника», комбо с «Ланч» / «Недельные бонусы», «Ежемесячные бонусы»;
- **не** бартер, **не** лист thanks, подарки ДР и т.п.

### Антидубли

- один ID Спасибо / одна карта Teams — не более одного раза в файле;
- ID уже у другого держателя → ошибка строки;
- та же пара ID + карта уже в БД → «уже привязано» (пропуск, можно включить «Применить дубли»);
- у держателя другой ID → нужен флаг «Заменить конфликты».

Повторная загрузка с теми же данными **идемпотентна** (без второй карты).

## API для Спасибо (v1)

| Метод | Назначение |
|-------|------------|
| `GET /api/spasibo/card?user_id=` | Баланс, short code, URL карты (read-only) |
| `POST /api/spasibo/redeem` | Обмен спасибок → credit на связанную карту |

Аутентификация: заголовок `X-Spasibo-Key` (`SPASIBO_API_KEY`, fallback `IIKO_API_KEY`).  
Redeem: обязателен `Idempotency-Key`. Тело: `spasibo_user_id`, `bonus_amount_rub` (рубли на карте), `comment`.
